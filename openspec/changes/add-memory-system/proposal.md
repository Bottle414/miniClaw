## 动机

miniClaw 目前维护单一消息历史，同时用作持久对话记录和直接模型输入。这使得难以分离持久会话事实、临时工作状态和特定模型的上下文构建，尤其是当对话增长并需要选择性保留、注入、丢弃或摘要时。

## 变更内容

- 引入基础记忆系统，包含会话记忆和工作记忆两个概念。
- 保留现有完整 `messages` 存储作为权威对话记录。
- 新增 `contextMessages` 作为面向模型的消息列表，由记忆和消息历史构建。
- 重构或替换当前 Message Handler 的职责，使消息存储、记忆更新和上下文构建分离。
- 新增上下文构建器，可在模型调用前选择性保留、丢弃、注入和摘要上下文。
- 新增简单初始摘要模块，设计为可替换或可扩展。
- 高级上下文溢出策略和复杂摘要策略推迟到后续变更。

## 能力

### 新增能力
- `memory-system`：定义 miniClaw 对话的会话记忆、工作记忆、面向模型的上下文构建和基础摘要行为。

### 修改能力
- `provider-chat`：模型对话请求将使用上下文构建器生成的 `contextMessages`，而非直接使用完整权威 `messages` 历史。

## 影响

- 受影响代码：消息处理、对话请求组装、存储对话数据的 ReAct 状态或会话状态，以及 Provider 对话/消息流的测试。
- API/数据模型：在现有 `messages` 旁引入 `contextMessages`；可能新增记忆相关类型和上下文构建接口。
- 依赖：基础实现无需新增外部依赖。
- 系统：影响所有 Provider 接收模型输入的方式，同时保留现有完整对话历史用于 UI、持久化和调试。
