## 背景

miniClaw 当前使用单一 `messages` 数组同时作为权威对话日志和 Provider 请求输入。`apps/runtime/src/index.ts` 将该数组直接传递给旧版对话路径和 ReAct 循环，而 ReAct 循环将 `state.messages` 直接传递给 `provider.chatStream()`。工具执行通过 `messageHandler` 混入 `utils/message.ts`，导致消息记录、工具消息创建和模型上下文组装的职责耦合。

新的记忆系统应引入更清晰的边界，同时不丢失现有完整消息历史。实现应小巧且面向基础：保留 `messages` 作为完整对话记录，引入 `contextMessages` 用于模型调用，将高级溢出处理留待后续。

## 目标 / 非目标

**目标：**
- 保留 `messages` 作为权威完整会话消息历史。
- 引入会话记忆，用于持久会话级事实和注入上下文。
- 引入工作记忆，用于临时迭代/任务上下文。
- 引入上下文构建器，从消息和记忆状态创建面向模型的 `contextMessages`。
- 在上下文构建流程中支持保留、丢弃、注入和摘要操作。
- 重构 Message Handler 职责，使工具处理和上下文构建不再耦合。
- 首先使用简单确定性摘要器，接口允许后续更丰富的摘要实现。

**非目标：**
- 本变更不实现跨进程或跨项目的持久记忆存储。
- 暂不实现复杂的 token 计数、语义检索、向量搜索或 LLM 生成摘要。
- 暂不完整解决超出 Provider 限制的上下文问题；仅提供基础摘要/裁剪基础。
- 不改变 Provider 适配器的传输格式，仅传递已构建的 `contextMessages` 作为请求消息。

## 决策

1. **将记忆作为运行时状态引入，而非 Provider 状态。**
   - 决策：在运行时层代码下新增记忆/会话/上下文构建模块，在 Provider 请求前调用。
   - 理由：Provider 应继续负责 API 传输和类型转换，不负责对话策略。
   - 备选方案：在 Provider 适配器内构建上下文。被否决，因为会在各 Provider 间重复策略并模糊适配器职责。

2. **保留 `messages`，新增 `contextMessages`。**
   - 决策：继续将所有用户、助手和工具消息追加到 `messages`；在模型调用前派生 `contextMessages`。
   - 理由：UI、调试、持久化和未来回放需要完整历史，而模型输入需要选择性塑造。
   - 备选方案：在裁剪或摘要时原地修改 `messages`。被否决，因为会破坏权威历史。

3. **拆分会话记忆和工作记忆。**
   - 决策：会话记忆用于对话级保留上下文，工作记忆用于临时任务/迭代状态。
   - 理由：会话事实和临时推理/工具观察有不同的生命周期和选择规则。
   - 备选方案：使用一个通用记忆袋。被否决，因为会使保留和清理规则模糊。

4. **使上下文构建器策略显式且可测试。**
   - 决策：上下文构建器接受权威消息加记忆状态，返回带元数据的 `contextMessages`，描述保留、注入、摘要和丢弃的部分。
   - 理由：使上下文策略可独立于 Provider 测试，将未来溢出工作局部化。
   - 备选方案：在 `index.ts` 和 ReAct 循环中内联上下文塑造。被否决，因为会重复策略并使 ReAct/非 ReAct 行为分化。

5. **从确定性摘要开始。**
   - 决策：添加简单摘要器，可使用确定性格式将旧消息压缩为合成系统/上下文消息。
   - 理由：提供扩展点和基线行为，无需增加另一次模型调用或依赖。
   - 备选方案：立即使用配置的 LLM 进行摘要。被否决，因为会引入递归、延迟、错误处理和成本问题。

6. **将 Message Handler 重构为聚焦的工具函数。**
   - 决策：重命名或拆分当前 `messageHandler` 职责，使工具调用到工具消息的处理与记忆/上下文处理分离。
   - 理由：当前名称暗示通用消息编排，但仅执行工具；记忆系统需要更清晰的所有权。
   - 备选方案：继续扩展 `messageHandler`。被否决，因为会增加耦合并恶化现有设计问题。

## 风险 / 权衡

- 上下文与权威历史偏离 → 缓解：始终先将真实对话消息追加到 `messages`，再从中派生 `contextMessages`。
- ReAct 循环行为意外变化 → 缓解：添加上下文构建测试，确保 ReAct 仍在状态/历史中记录所有助手/工具消息。
- 摘要消息可能隐藏重要工具细节 → 缓解：初始策略应保留近期消息和工具观察，仅摘要较旧的合格消息。
- 上下文构建器过早过度抽象 → 缓解：保持接口小巧，仅实现保留、丢弃、注入和摘要所需操作。
- 会话记忆与持久记忆的术语混淆 → 缓解：文档说明本变更中会话记忆是会话作用域的内存状态。

## 迁移计划

1. 添加记忆和上下文构建器类型/模块及单元测试。
2. 将上下文构建器集成到旧版对话和流式路径，使 Provider 调用使用 `contextMessages`。
3. 将上下文构建器集成到 ReAct Act 阶段，使 ReAct 状态保持权威但 Provider 输入为派生。
4. 重构 `messageHandler` 命名/职责，聚焦工具消息处理。
5. 验证现有对话、流式和 ReAct 测试继续通过，或更新以适应新的面向模型上下文行为。

回滚简单：Provider 调用可切回直接传递 `messages`/`state.messages`，保留新模块不使用。
