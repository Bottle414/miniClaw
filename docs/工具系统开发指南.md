# 工具系统开发指南

## 概述

工具系统采用统一注册模式，工具定义使用内部 `LLMTool` 格式，通过适配器 `transformTools` 转换为具体 LLM 提供商格式后提供给模型。

核心流程：

```
工具定义 (LLMTool) → ToolHandler 注册 → transformTools 转换 → 提供给 LLM
                                                          ↓
LLM 返回 tool_call → ToolHandler.call() 执行 → 返回结果给 LLM
```

## 工具命名规范

采用 **`模块.功能`** 格式，使用 camelCase：

| 模块    | 示例工具名            | 说明           |
| ------- | --------------------- | -------------- |
| weather | `weather.getWeather`  | 获取天气       |
| weather | `weather.getForecast` | 获取天气预报   |
| fs      | `fs.readFile`         | 读取文件       |
| fs      | `fs.writeFile`        | 写入文件       |
| net     | `net.httpRequest`     | 发送 HTTP 请求 |

规则：

- 模块名小写，功能名 camelCase
- 命名需清晰表达意图，避免缩写

## 添加新工具

### 1. 创建工具文件

在 `apps/runtime/src/tools/` 下创建文件，如 `fs.ts`：

```ts
import type { LLMTool } from "../types/llm"

export const fsReadFile = {
    definition: {
        name: "fs.readFile",
        description: "读取指定路径的文件内容",
        parameters: {
            type: "object",
            properties: {
                path: {
                    type: "string",
                    description: "文件路径"
                },
                encoding: {
                    type: "string",
                    description: "文件编码，默认 utf-8"
                }
            },
            required: ["path"]
        }
    } satisfies LLMTool,
    executor: (params: Record<string, unknown>): string => {
        const { path, encoding = "utf-8" } = params as { path: string; encoding?: string }
        // 实现逻辑
        return "file content"
    }
}
```

### 2. 注册工具

在 `apps/runtime/src/index.ts` 的 `createRuntime` 中导入并注册：

```ts
import { fsReadFile } from "./tools/fs"

// 在 createRuntime 内
const handlerTool = createToolHandler({
    sessionsRoot,
    onMetricsUpdate: options.onMetricsUpdate,
    onPermissionCheck: options.onPermissionCheck,
    permissionConfig: options.permissionConfig
})
handlerTool.register(weatherGetWeather.definition, weatherGetWeather.executor, weatherGetWeather.metadata)
handlerTool.register(fsReadFile.definition, fsReadFile.executor)
```

调用方（TUI/Server）需从 `projectRoot` 加载 `permission.json` 并传入：

```ts
import { loadPermissionConfig } from "@mini-claw/runtime"

const runtime = createRuntime({
    sessionsRoot: path.resolve(projectRoot, ".sessions"),
    permissionConfig: loadPermissionConfig(projectRoot),
    // ...
})
```

### 3. 完成

工具会自动包含在 `handlerTool.getToolDefinitions()` 返回的列表中，经 `transformTools` 转换后提供给 LLM。

## ToolHandler API

```ts
/** 工具处理器配置 */
interface ToolHandlerOptions {
    /** 权限配置 */
    permissionConfig?: PermissionConfig
    /** 权限确认回调 */
    onPermissionCheck?: (toolName: string) => Promise<boolean>
    /** 指标更新回调 */
    onMetricsUpdate?: (snapshot: MetricsSnapshot) => void
    /** session 根目录（用于 logging middleware） */
    sessionsRoot?: string
}

/** 创建工具处理器 */
function createToolHandler(options?: ToolHandlerOptions): ToolHandler

/** ToolHandler 实例方法 */
interface ToolHandler {
    /** 注册工具 */
    register(definition: LLMTool, executor: ToolExecutor, metadata?: ToolMetadata): void

    /** 设置/更新工具 */
    set(definition: LLMTool, executor: ToolExecutor, metadata?: ToolMetadata): void

    /** 通过名称获取工具 */
    get(name: string): ToolEntry | undefined

    /** 调用工具 */
    call(name: string, params: Record<string, unknown>, sessionId?: string): Promise<ToolResult>

    /** 获取所有工具定义 (LLMTool 格式) */
    getToolDefinitions(): LLMTool[]

    /** 是否已注册 */
    has(name: string): boolean
}
```

> **注意**: `ToolHandler` 不再是全局单例，而是由 `createRuntime` 创建并注入到 ReAct 循环。`sessionsRoot` 参数用于 logging 中间件的文件输出路径。Metrics 中间件通过 `onMetricsUpdate` 回调推送指标快照，不再直接写文件。权限控制通过 `permissionConfig` 和 `onPermissionCheck` 回调实现。

## 类型定义

工具定义使用 `LLMTool`（位于 `types/llm/tool.ts`）：

```ts
interface LLMTool {
    name: string
    description: string
    parameters?: LLMFunctionParameters
}

interface LLMFunctionParameters {
    type?: string
    properties?: Record<string, unknown>
    required?: string[]
    [key: string]: unknown
}
```

工具执行函数类型：

```ts
type ToolExecutor = (params: Record<string, unknown>) => string
```

## 格式转换

### 请求方向：LLMTool → 提供商格式

`transformTools` 将内部 `LLMTool[]` 转换为具体提供商格式，例如：

```ts
// LLMTool (内部格式)
{ name: "weather.getWeather", description: "获取天气", parameters: {...} }

// ↓ transformTools 转换

// DeepSeekTool (DeepSeek 格式)
{ type: "function", function: { name: "weather-getWeather", description: "获取天气", parameters: {...} } }
```

> **DeepSeek 特殊处理**：DeepSeek API 要求工具名匹配 `^[a-zA-Z0-9_-]+$`，不支持 `.` 字符。适配层 `transformTools` 会自动将 `.` 替换为 `-`（如 `weather.getWeather` → `weather-getWeather`），内部代码始终使用 `.` 格式。

### 响应方向：提供商格式 → LLMToolCall

`parseToolCalls` 将 LLM 返回的 tool_calls 转换为内部 `LLMToolCall[]` 格式，例如：

```ts
// DeepSeek 返回格式
{ id: "call_xxx", type: "function", function: { name: "weather-getWeather", arguments: '{"city":"上海"}' } }

// ↓ parseToolCalls 转换

// LLMToolCall (内部格式)
{ id: "call_xxx", name: "weather.getWeather", arguments: '{"city":"上海"}' }
```

转换要点：

- 嵌套的 `function.name` 提升为顶层 `name`
- 工具名中 `-` 还原为 `.`（与 `transformTools` 中 `.` → `-` 对应）

当前适配器位于 `adaptor/deepseek/index.ts`，新增提供商时需实现对应的 `transformTools` 和 `parseToolCalls`。
