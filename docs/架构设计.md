# 架构设计

## 整体架构

miniClaw 采用分层架构，各层职责单一、通过统一类型层解耦。Runtime 与 UI 完全解耦，通过 `createRuntime` 工厂方法创建运行时实例，支持多界面接入（TUI、Web 等）。

```
┌─────────────────────────────────────────────────────┐
│               界面层 (apps/tui, apps/web)            │
│       加载 dotenv / 调用 createRuntime / 渲染输出      │
├─────────────────────────────────────────────────────┤
│               Runtime 工厂 (runtime.ts)              │
│   createRuntime → chat / sessionManager / config     │
├─────────────────────────────────────────────────────┤
│                   接入层 (provider/)                  │
│       Provider 初始化 / API 调用 / 流式输出            │
├─────────────────────────────────────────────────────┤
│                   适配层 (adaptor/)                   │
│    统一类型 ↔ 提供商类型 双向转换 / 流式 chunk          │
├─────────────────────────────────────────────────────┤
│              ReAct 循环层 (react/)                    │
│     Think-Act-Observe-Decide 循环 / 状态机            │
├─────────────────────────────────────────────────────┤
│               记忆层 (memory/)                        │
│    记忆存储 / 上下文构建器 / 摘要压缩                    │
├─────────────────────────────────────────────────────┤
│              工具注册中心 (tools/)                     │
│          工具定义注册 / 查找 / 执行调度                  │
├─────────────────────────────────────────────────────┤
│             消息处理中心 (utils/message)               │
│        工具调用解析 → 工具执行 → 结果回填                │
├─────────────────────────────────────────────────────┤
│              配置层 (utils/config)                    │
│         配置校验 / RuntimeConfig 合并                  │
├─────────────────────────────────────────────────────┤
│               类型层 (types/)                         │
│  统一 LLM 类型 / 提供商类型 / 配置类型 / 事件类型        │
└─────────────────────────────────────────────────────┘
```

## Runtime 工厂

**文件**: `src/index.ts` + `src/runtime.ts`

`createRuntime` 是 runtime 对外的唯一入口，封装所有初始化逻辑，返回 `{ chat, sessionManager, config }` 三个公共 API。所有配置由调用方显式传入，不依赖 `process.env` 或 `process.cwd()`。

### createRuntime 选项

```ts
interface RuntimeOptions {
	apiKey: string // LLM API Key（必需）
	provider?: LLMProviderType // LLM 提供商（"deepseek" | "glm"，默认 deepseek）
	baseUrl?: string // LLM API Base URL
	model?: string // 模型名称
	soulPrompt?: string // 系统人格提示
	userPrompt?: string // 用户自定义提示词（注入到 soulPrompt 之后）
	sessionId?: string // 加载已有 session
	sessionName?: string // 创建新 session 时使用
	sessionsRoot: string // Session 存储目录路径（必需）
	permissionConfig?: PermissionConfig // 权限配置
	onPermissionCheck?: (toolName: string) => Promise<boolean> // 权限确认回调
	onMetricsUpdate?: (snapshot: MetricsSnapshot) => void // 指标更新回调
}
```

### Runtime 返回类型

```ts
interface Runtime {
	chat(userInput: string, options?: ChatOptions): AsyncIterable<RuntimeEvent>
	sessionManager: SessionManager
	config: Config
}
```

### 初始化流程

```
createRuntime(options)
  ├─ createConfig(options)           → Config
  ├─ Provider 初始化（根据 options.provider 选择）:
  │   ├─ "deepseek" → DeepSeekProvider().init(config)
  │   └─ "glm"      → GLMProvider().init(config)
  ├─ createRuntimeMemoryState()      → Memory
  ├─ createLLMSummarizer(provider, config) → Summarizer
  ├─ createFileSystemMemoryStore(sessionsRoot) → SessionStore
  ├─ createSessionManager(store)     → SessionManager
  └─ createToolHandler({ sessionsRoot, permissionConfig, onPermissionCheck, onMetricsUpdate }) → ToolHandler
```

### chat 方法

`chat(userInput, options?)` 内部调用 `executeReActLoop`，透传 `RuntimeEvent`，循环完成后自动更新 messages/memory/session 状态并持久化 session。

- 首次调用时自动初始化 session（加载或创建）
- 调用方只需传入 `userInput` 和可选的 `contextOptions`
- messages、memory、summarizer 由 runtime 内部管理，不暴露给调用方

### ReAct 循环模式

```
用户输入 → 初始化 ReAct 状态
  → Think 阶段: 准备 LLM 调用
  → Act 阶段: provider.chatStream() → 解析响应
    → 有 toolCalls?
      → 是: Observe 阶段: 执行工具 → 记录观察结果 → Decide 阶段
      → 否: Decide 阶段: 检查终止条件
  → 应该终止?
    → 是: 返回最终答案
    → 否: 增加迭代次数 → 继续下一轮 Think
```

## 界面层

### TUI (`apps/tui`)

终端交互界面，职责：

- 加载 dotenv 环境变量
- 调用 `createRuntime` 创建运行时实例
- 使用 readline 获取用户输入
- 消费 `RuntimeEvent` 渲染输出到终端

```ts
// apps/tui/src/index.ts
import { loadPermissionConfig } from "@mini-claw/runtime"

const runtime = createRuntime({
	apiKey: process.env.API_KEY!,
	baseUrl: process.env.DEEPSEEK_BASE_URL,
	model: process.env.DEEPSEEK_MODEL,
	sessionId: process.env.SESSION_ID,
	sessionName: process.env.SESSION_NAME,
	sessionsRoot: path.resolve(projectRoot, ".sessions"),
	permissionConfig: loadPermissionConfig(projectRoot)
})

for await (const event of runtime.chat(userInput)) {
	// 渲染事件到终端
}
```

### Web (`apps/web`)

React Web 界面，通过 SSE 连接 Server 端，不直接调用 runtime。架构如下：

```
Web (React + Zustand)
  ├─ SSE Client (lib/sse-client.ts)         → 连接 Server SSE 端点
  ├─ Message Merger (lib/message-merger.ts)  → 合并流式消息（含 reasoning-delta）
  ├─ Event Processor (lib/runtime-event-processor.ts) → 分发 SSE 事件到 Store
  ├─ Stores (Zustand)
  │   ├─ chat-store.ts   → 聊天消息、session 管理
  │   ├─ runtime-store.ts → Inspector 数据（迭代、阶段、工具记录）
  │   ├─ settings-store.ts → 用户配置、权限配置、模型切换
  │   └─ ui-store.ts     → UI 状态（侧边栏、Inspector 面板等）
  ├─ Components
  │   ├─ Chat/            → 聊天主区域
  │   │   ├─ ChatMessage/ → 消息气泡（含思考过程折叠展示）
  │   │   ├─ ChatInput/   → 输入框 + 发送 + 语音输入 + 模型切换
  │   │   └─ MessageList/ → 消息列表
  │   ├─ Sidebar/         → 会话列表 + 设置入口
  │   │   └─ SettingsModal/ → 设置弹窗
  │   │       ├─ PersonalizationTab/ → 个性化（称呼/身份/性格）
  │   │       ├─ ApiKeyTab/          → API Key 配置（DeepSeek/GLM）
  │   │       └─ PermissionTab/      → 权限配置
  │   └─ Inspector/       → Runtime Inspector 面板
  │       ├─ EventsTab/   → ReAct 迭代时间线
  │       ├─ ToolsTab/    → 工具执行记录
  │       ├─ MetricsTab/  → 工具指标
  │       └─ SessionTab/  → Session 信息
  ├─ Hooks
  │   └─ speech.ts        → useSpeechRecognition（Web Speech API 封装）
  └─ API Client           → REST 调用（session 列表、metrics、user-config 等）
```

SSE 事件处理双通道：

- `message-merger.ts`：处理 text-delta、reasoning-delta 等聊天消息合并
- `runtime-event-processor.ts`：处理 phase-change、tool-execute 等 Inspector 数据

每次发送新消息时，`chat-store` 调用 `clearRuntime()` + `resetRuntimeEventProcessor()` 清空 Inspector 数据。

#### 思考过程展示

Assistant 消息可包含 `reasoning` 字段（来自 `reasoning-delta` 事件的累积），在 `ChatMessage` 组件中使用 `Collapse` 折叠展示：

- 思考中自动展开，思考完毕自动折叠
- 用户手动操作后不再自动折叠
- reasoning 数据不注入到 LLM 上下文，仅用于 UI 渲染
- 历史消息的 reasoning 从 session 的 `reasoning.json` 恢复，通过 `messageIndex` 一一对应

#### 设置系统

设置弹窗（`SettingsModal`）包含三个 Tab：

- **个性化** (`PersonalizationTab`): 称呼、身份、详情、助手性格（soul）
- **API_KEY** (`ApiKeyTab`): DeepSeek / GLM API Key 配置，已配置的 Key 服务端返回脱敏掩码
- **权限配置** (`PermissionTab`): 工具权限（allow/check/deny），JSON 编辑

设置数据通过 `settings-store.ts` 管理，持久化到服务端 `userConfig.json` 和 `permission.json`。

#### 模型切换

聊天输入区域底部提供模型下拉选择（`Select`），支持 DeepSeek / GLM 切换。切换时调用 `settingsStore.switchModel()` 更新 `userConfig.model`，下次发送消息时 Server 根据 model 推断 provider 和 apiKey。

#### 语音输入

通过 `hooks/speech.ts` 的 `useSpeechRecognition` 封装 Web Speech API，配置 `lang: "zh-CN"`、`continuous: false`、`interimResults: true`。录音按钮在 `ChatInput` 中，录制中显示 loading 状态，识别结果追加到输入框。

## 各层介绍

### ReAct 循环层

**文件**: `src/react/`

实现 ReAct (Reasoning + Acting) 模式的核心逻辑：

- **状态管理** (`state.ts`): 不可变状态对象，跟踪迭代次数、阶段、消息历史
- **终止逻辑** (`terminator.ts`): 多级终止检查（最终答案、迭代限制、错误、空响应）
- **循环编排** (`loop.ts`): 协调 Think → Act → Observe → Decide 四个阶段

`executeReActLoop` 通过 `ReActLoopConfig` 接收 `toolHandler` 实例（由 `createRuntime` 创建并注入），不依赖全局单例。

```
ReActState {
  iteration: number          // 当前迭代次数
  phase: RuntimePhase        // 当前阶段
  messages: LLMMessage[]     // 消息历史
  shouldTerminate: boolean   // 是否终止
  terminationReason?: string // 终止原因
}
```

### 事件系统

miniClaw 采用两层事件架构：

```
ProviderEvent (types/event/provider-event.ts)
  = TextDeltaEvent | ToolCallStartEvent | ToolCallDeltaEvent
  | ToolCallEndEvent | FinishEvent | ErrorEvent

RuntimeEvent (types/event/runtime-event.ts)
  = ProviderEvent (provider stream 透传)
  | IterationStartEvent | PhaseChangeEvent
  | ToolExecuteEvent | ToolResultEvent | LoopEndEvent (runtime lifecycle)
```

| 事件层级                 | 类型            | 说明                 |
| ------------------------ | --------------- | -------------------- |
| ProviderEvent            | text-delta      | LLM 文本增量         |
| ProviderEvent            | reasoning-delta | LLM 思考过程增量     |
| ProviderEvent            | tool-call-start | LLM 工具调用开始     |
| ProviderEvent            | tool-call-delta | LLM 工具调用参数增量 |
| ProviderEvent            | tool-call-end   | LLM 工具调用结束     |
| ProviderEvent            | finish          | LLM 响应完成         |
| ProviderEvent            | error           | 流式处理错误         |
| RuntimeEvent (lifecycle) | iteration-start | 迭代开始             |
| RuntimeEvent (lifecycle) | phase-change    | 阶段转换             |
| RuntimeEvent (lifecycle) | tool-execute    | 工具执行开始         |
| RuntimeEvent (lifecycle) | tool-result     | 工具执行结果         |
| RuntimeEvent (lifecycle) | loop-end        | 循环结束             |

### 接入层

**文件**: `src/provider/`

Provider 封装了 LLM API 的调用细节，对上层暴露统一的接口：

- **chat** — 非流式调用，返回完整 `LLMResponse`
- **chatStream** — 流式调用，返回 `AsyncIterable<ProviderEvent>`

每个提供商实现为一个函数+闭包：

- **DeepSeekProvider** — 持有 OpenAI 兼容客户端，内部调用 DeepSeek API
- **GLMProvider** — 持有 OpenAI 兼容客户端，内部调用智谱 GLM API
- 初始化时接收 Config，创建对应的 API 客户端
- 调用时委托适配层做类型转换，处理认证/限流/网络等错误

GLM API 与 OpenAI 格式完全兼容，因此 GLMProvider 复用 `deepseekAdapter`，无需单独实现适配器。

```ts
const provider = DeepSeekProvider() // 或 GLMProvider()
provider.init(config)

// 非流式
const response = await provider.chat({ messages, model, tools })

// 流式
for await (const event of provider.chatStream({ messages, model, tools })) {
	// event: ProviderEvent (text-delta / reasoning-delta / tool-call-start / tool-call-delta / finish / ...)
}
```

### 适配层

**文件**: `src/adaptor/deepseek/`

实现统一 LLM 类型与提供商特定类型之间的双向转换，是接入层与类型层之间的桥梁：

| 方向          | 方法                     | 说明                                                       |
| ------------- | ------------------------ | ---------------------------------------------------------- |
| 统一 → 提供商 | `transformRequest()`     | LLMRequest → DeepSeekChatCompletionRequest                 |
| 统一 → 提供商 | `transformTools()`       | LLMTool[] → DeepSeekTool[]，同时 `.` → `-`                 |
| 提供商 → 统一 | `transformResponse()`    | DeepSeekChatCompletionResponse → LLMResponse               |
| 提供商 → 统一 | `parseToolCalls()`       | DeepSeekToolCallResponse[] → LLMToolCall[]，同时 `-` → `.` |
| 流式 → 统一   | `transformStreamChunk()` | DeepSeekChatCompletionChunk → ProviderEvent                |

工具名中 `.` 与 `-` 的互转逻辑封装在此层，其他层禁止重复实现。

### 记忆层

**文件**: `src/memory/`

分层记忆管理，确保权威消息不可变，面向模型的上下文可按需裁剪：

- **MemoryStore** (`store.ts`): 权威消息存储，所有消息追加操作通过 `append()` 进行，原始 `messages` 不可变
- **上下文构建器** (`context-builder.ts`): 从权威消息生成面向模型的 `contextMessages`，支持保留、丢弃、注入、摘要四种操作
- **摘要器** (`summarizer.ts`): 将旧消息压缩为确定性摘要，节省上下文窗口。当前为简单摘要器，设计为可替换扩展点
- **类型** (`types.ts`): 记忆层相关类型定义

```
权威消息 (messages[])
  │
  ▼ 上下文构建器
  │  ├─ 保留: 保留近期 N 条消息
  │  ├─ 丢弃: 丢弃过旧或无关消息
  │  ├─ 注入: 注入系统消息
  │  └─ 摘要: 将旧消息压缩为摘要消息
  │
  ▼
面向模型的上下文 (contextMessages[])
```

### 工具注册中心

**文件**: `src/tools/`

`createToolHandler` 创建工具处理器实例，以 `Map<name, ToolEntry>` 维护工具表：

- **创建**: `createToolHandler(options?)` 创建实例，options 包含 sessionsRoot（logging 中间件）、permissionConfig/onPermissionCheck（权限控制）、onMetricsUpdate（指标回调）
- **注册**: 每个工具导出 `{ definition, executor }`，通过 `handler.register()` 注册
- **查找**: `handler.getToolDefinitions()` 返回所有工具定义，供 LLM 请求使用
- **执行**: `handler.call(name, params, sessionId?)` 按名称调度执行，返回 ToolResult

工具处理器实例由 `createRuntime` 创建并注入到 ReAct 循环，不使用全局单例。新增工具只需在 `tools/` 下创建文件并在 `createRuntime` 中注册，无需修改其他层。

### 消息处理中心

**文件**: `src/utils/message.ts` + `src/utils/tool.ts`

负责将 LLM 返回的工具调用解析为可执行的操作，并回填结果：

1. **messageHandler** — 接收 LLM 响应中的 `tool_calls`，通过适配层的 `parseToolCalls()` 转为统一格式
2. **useTool** — 遍历工具调用列表，通过 `toolHandler.call()` 逐个执行，将结果构造为 `LLMToolMessage[]`（需传入 toolHandler 实例）

```
LLM 响应 tool_calls → parseToolCalls() → LLMToolCall[]
  → toolHandler.call() → 执行结果
    → 构造 LLMToolMessage[] → 追加到消息历史
```

### 配置层

**文件**: `src/utils/config.ts` + `src/prompts/system.ts`

配置分为两层：

| 类型          | 说明           | 字段                                                                               |
| ------------- | -------------- | ---------------------------------------------------------------------------------- |
| RuntimeConfig | 运行时持久配置 | systemPrompt, maxIterations, maxToolRetryTimes, maxSendRetryTimes, onMetricsUpdate |
| TaskConfig    | 单次任务配置   | baseURL, apiKey, model, tools, stream, soulPrompt, userPrompt                      |

`createConfig(options)` 接收 `CreateConfigOptions`（apiKey, baseUrl, model, soulPrompt, userPrompt, provider），校验必要字段并合并默认值。`Config` 类型为两者的交集。

各提供商的默认配置：

| 提供商   | 默认 Base URL                          | 默认模型        |
| -------- | -------------------------------------- | --------------- |
| deepseek | `https://api.deepseek.com`             | `deepseek-chat` |
| glm      | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash`   |

`soulPrompt` 支持自定义角色人格，默认使用 `prompts/soul.ts` 中的 Soul 角色提示词。`userPrompt` 由 Server 端根据 `userConfig`（称呼、身份、详情）动态生成，注入到 soulPrompt 之后。

### 类型层

**文件**: `src/types/`

定义与具体提供商无关的统一抽象类型，是各层之间的契约：

| 子模块             | 说明                                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| `types/llm/`       | 统一 LLM 类型：LLMMessage, LLMRequest, LLMResponse, LLMTool, LLMToolCall 等 |
| `types/providers/` | Provider 接口 + 各提供商特定类型（含流式响应类型）                          |
| `types/config/`    | RuntimeConfig, TaskConfig, Config                                           |
| `types/event/`     | ProviderEvent（provider 流式事件）+ RuntimeEvent（runtime 对外事件）        |
| `types/react/`     | ReAct 循环类型（Phase, State, Action, Observation, Termination）            |
| `types/runtime.ts` | Runtime 工厂类型（RuntimeOptions, Runtime, ChatOptions）                    |

业务层禁止直接使用 `openai` 包的类型，必须通过类型层 + 适配层访问。

## 数据流

### 完整请求-响应流程（非流式）

```
用户输入 "上海天气"
  │
  ▼
构造 LLMUserMessage { role: "user", content: "上海天气" }
  │
  ▼ 追加到 messages[]
构造 LLMRequest { messages, model: "deepseek-chat", tools: [...] }
  │
  ▼ provider.chat(req)
  │
  ▼ adaptor.transformRequest(llmRequest)
  │   → DeepSeekChatCompletionRequest
  │   → messages 转换: LLMMessage[] → DeepSeekMessage[]
  │   → tools 转换: LLMTool[] → DeepSeekTool[] (工具名 "." → "-")
  │
  ▼ OpenAI 客户端调用 DeepSeek API
  │
  ▼ 收到 DeepSeekChatCompletionResponse
  │
  ▼ adaptor.transformResponse(deepseekResponse)
  │   → LLMResponse { id, created, model, message: { content, toolCalls } }
  │   → tool_calls 解析: "-" → "." 还原工具名
  │
  ▼ 返回 LLMResponse
  │
  ├─ 无 toolCalls → 输出文本回复
  │
  └─ 有 toolCalls → messageHandler 处理
      │
      ▼ parseToolCalls() → LLMToolCall[]
      │
      ▼ toolHandler.call("weather.getWeather", { city: "上海" })
      │   → "sunny"
      │
      ▼ 构造 LLMToolMessage { role: "tool", toolCallId, content: "sunny" }
      │
      ▼ 追加 assistant 消息 + tool 消息到 messages[]
      │
      ▼ 递归 provider.chat() → LLM 生成最终回复
```

### 流式输出流程

```
用户输入
  │
  ▼
provider.chatStream(req)
  │
  ▼ adaptor.transformRequest(llmRequest) → DeepSeek 请求格式
  │
  ▼ OpenAI 客户端流式调用 DeepSeek API
  │
  ▼ 逐 chunk 接收 DeepSeekChatCompletionChunk
  │
  ▼ adaptor.transformStreamChunk(chunk) → ProviderEvent
  │   ├─ { type: "text-delta", delta: "..." }        → 逐 token 文本输出
  │   ├─ { type: "tool-call-start", ... }             → 工具调用开始
  │   ├─ { type: "tool-call-delta", ... }             → 工具参数增量
  │   └─ { type: "finish", reason: "stop", usage }    → 生成完成
  │
  ▼ ReAct 循环透传 ProviderEvent + 发出 RuntimeLifecycleEvent
  │
  ▼ chat 方法透传 RuntimeEvent，界面层消费并渲染
```

### 类型转换流向

```
业务代码 (LLMRequest / LLMMessage / LLMTool)
  → adaptor.transformRequest()
    → 提供商请求格式 (DeepSeekChatCompletionRequest)
      → API 调用
        → 提供商响应格式 (DeepSeekChatCompletionResponse)
          → adaptor.transformResponse()
            → 业务代码 (LLMResponse)

流式:
提供商 chunk (DeepSeekChatCompletionChunk)
  → adaptor.transformStreamChunk()
    → ProviderEvent
    → ReAct 循环透传为 RuntimeEvent 的一部分
```

### 记忆层数据流

```
用户消息 / LLM 响应 / 工具结果
  │
  ▼ memoryStore.append()
  │  → 权威 messages[] 追加（不可变）
  │
  ▼ 上下文构建器 (每次 LLM 调用前)
  │  ├─ 保留近期消息
  │  ├─ 丢弃过旧消息
  │  ├─ 注入系统提示词
  │  └─ 摘要旧消息（可选）
  │
  ▼ 输出 contextMessages[]
  │
  ▼ adaptor.transformRequest() 使用 contextMessages 而非原始 messages
```
