# 架构设计

## 整体架构

miniClaw 采用分层架构，各层职责单一、通过统一类型层解耦：

```
┌─────────────────────────────────────────────────┐
│                   入口层 (index.ts)              │
│              Agent Loop 主循环 / CLI 交互         │
├─────────────────────────────────────────────────┤
│                   接入层 (provider/)             │
│           Provider 初始化 / API 调用 / 错误处理    │
├─────────────────────────────────────────────────┤
│                   适配层 (adaptor/)              │
│        统一类型 ↔ 提供商类型 双向转换              │
├─────────────────────────────────────────────────┤
│              工具注册中心 (tools/)               │
│          工具定义注册 / 查找 / 执行调度            │
├─────────────────────────────────────────────────┤
│             消息处理中心 (utils/message)          │
│        工具调用解析 → 工具执行 → 结果回填          │
├─────────────────────────────────────────────────┤
│              配置层 (utils/config)               │
│        环境变量加载 / 校验 / RuntimeConfig 合并    │
├─────────────────────────────────────────────────┤
│               类型层 (types/)                    │
│     统一 LLM 类型 / 提供商类型 / 配置类型          │
└─────────────────────────────────────────────────┘
```

## 各层介绍

### 入口层

**文件**: `src/index.ts`

Agent Loop 的主循环，负责：

- 加载环境变量与配置
- 初始化 Provider
- 维护对话消息历史
- 驱动用户输入 → LLM 调用 → 工具执行 → 回复输出的循环

```
用户输入 → 构造 UserMessage → provider.chat()
  → 返回 AssistantMessage
    → 有 toolCalls?
      → 是: 消息处理中心执行工具 → 构造 ToolMessage → 再次 provider.chat() (递归)
      → 否: 输出文本回复 → 等待下一轮用户输入
```

### 接入层

**文件**: `src/provider/`

Provider 封装了 LLM API 的调用细节，对上层暴露统一的 `chat(req: LLMRequest): Promise<LLMResponse>` 接口。每个提供商实现为一个函数+闭包：

- **DeepSeekProvider** — 持有 OpenAI 兼容客户端，内部调用 DeepSeek API
- 初始化时接收 Config，创建对应的 API 客户端
- 调用时委托适配层做类型转换，处理认证/限流/网络等错误

```ts
const provider = DeepSeekProvider()
provider.init(config)
const response = await provider.chat({ messages, model, tools })
```

### 适配层

**文件**: `src/adaptor/deepseek/`

实现统一 LLM 类型与提供商特定类型之间的双向转换，是接入层与类型层之间的桥梁：

| 方向          | 方法                  | 说明                                                       |
| ------------- | --------------------- | ---------------------------------------------------------- |
| 统一 → 提供商 | `transformRequest()`  | LLMRequest → DeepSeekChatCompletionRequest                 |
| 统一 → 提供商 | `transformTools()`    | LLMTool[] → DeepSeekTool[]，同时 `.` → `-`                 |
| 提供商 → 统一 | `transformResponse()` | DeepSeekChatCompletionResponse → LLMResponse               |
| 提供商 → 统一 | `parseToolCalls()`    | DeepSeekToolCallResponse[] → LLMToolCall[]，同时 `-` → `.` |

工具名中 `.` 与 `-` 的互转逻辑封装在此层，其他层禁止重复实现。

### 工具注册中心

**文件**: `src/tools/`

ToolHandler 是工具的统一注册与调度中心，以 `Map<name, ToolEntry>` 维护工具表：

- **注册**: 每个工具导出 `{ definition, executor }`，在 `tools/index.ts` 中通过 `toolHandler.register()` 注册
- **查找**: `toolHandler.getToolDefinitions()` 返回所有工具定义，供 LLM 请求使用
- **执行**: `toolHandler.call(name, params)` 按名称调度执行，返回字符串结果

新增工具只需在 `tools/` 下创建文件并注册，无需修改其他层。

### 消息处理中心

**文件**: `src/utils/message.ts` + `src/utils/tool.ts`

负责将 LLM 返回的工具调用解析为可执行的操作，并回填结果：

1. **messageHandler** — 接收 LLM 响应中的 `tool_calls`，通过适配层的 `parseToolCalls()` 转为统一格式
2. **useTool** — 遍历工具调用列表，通过 `toolHandler.call()` 逐个执行，将结果构造为 `LLMToolMessage[]`

```
LLM 响应 tool_calls → parseToolCalls() → LLMToolCall[]
  → toolHandler.call() → 执行结果
    → 构造 LLMToolMessage[] → 追加到消息历史
```

### 配置层

**文件**: `src/utils/config.ts` + `src/prompts/system.ts`

配置分为两层：

| 类型          | 说明           | 字段                                                              |
| ------------- | -------------- | ----------------------------------------------------------------- |
| RuntimeConfig | 运行时持久配置 | systemPrompt, maxIterations, maxToolRetryTimes, maxSendRetryTimes |
| TaskConfig    | 单次任务配置   | baseURL, apiKey, model, tools, userPrompt                         |

`createConfig(env)` 从环境变量加载配置，提供默认值并校验必要字段（apiKey 非空、baseURL 格式合法）。`Config` 类型为两者的交集。

### 类型层

**文件**: `src/types/`

定义与具体提供商无关的统一抽象类型，是各层之间的契约：

| 子模块             | 说明                                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| `types/llm/`       | 统一 LLM 类型：LLMMessage, LLMRequest, LLMResponse, LLMTool, LLMToolCall 等 |
| `types/providers/` | Provider 接口 + 各提供商特定类型（如 DeepSeekChatCompletionRequest）        |
| `types/config/`    | RuntimeConfig, TaskConfig, Config                                           |

业务层禁止直接使用 `openai` 包的类型，必须通过类型层 + 适配层访问。

## 数据流

### 完整请求-响应流程

```
用户输入 "上海天气"
  │
  ▼
构造 LLMUserMessage { role: "user", content: [{ type: "text", text: "上海天气" }] }
  │
  ▼ 追加到 messages[]
构造 LLMRequest { messages, model: "deepseek-chat", tools: [...] }
  │
  ▼ provider.chat(req)
  │
  ▼ adaptor.transformRequest(llmRequest)
  │   → DeepSeekChatCompletionRequest
  │   → messages 转换: LLMMessage[] → DeepSeekMessage[]
  │   → tools 转换: LLMTool[] → DeepSeekTool[] (工具名 "." → "-")
  │
  ▼ OpenAI 客户端调用 DeepSeek API
  │
  ▼ 收到 DeepSeekChatCompletionResponse
  │
  ▼ adaptor.transformResponse(deepseekResponse)
  │   → LLMResponse { id, created, model, message: { content, toolCalls } }
  │   → tool_calls 解析: "-" → "." 还原工具名
  │
  ▼ 返回 LLMResponse
  │
  ├─ 无 toolCalls → 输出文本回复
  │
  └─ 有 toolCalls → messageHandler 处理
      │
      ▼ parseToolCalls() → LLMToolCall[]
      │
      ▼ toolHandler.call("weather.getWeather", { city: "上海" })
      │   → "sunny"
      │
      ▼ 构造 LLMToolMessage { role: "tool", toolCallId, content: "sunny" }
      │
      ▼ 追加 assistant 消息 + tool 消息到 messages[]
      │
      ▼ 递归 provider.chat() → LLM 生成最终回复
```

### 类型转换流向

```
业务代码 (LLMRequest / LLMMessage / LLMTool)
  → adaptor.transformRequest()
    → 提供商请求格式 (DeepSeekChatCompletionRequest)
      → API 调用
        → 提供商响应格式 (DeepSeekChatCompletionResponse)
          → adaptor.transformResponse()
            → 业务代码 (LLMResponse)
```

## 目录结构

```
src/
├── index.ts              # 入口，Agent Loop 主循环
├── provider/             # 接入层：Provider 实现
│   ├── index.ts          #   导出与类型重导出
│   └── deepseek.ts       #   DeepSeek Provider (函数+闭包)
├── adaptor/              # 适配层：类型转换
│   └── deepseek/
│       └── index.ts      #   DeepSeek 适配器 (transformRequest/Response/Tools/parseToolCalls)
├── tools/                # 工具注册中心
│   ├── index.ts          #   ToolHandler 类 + 全局实例 + 工具注册
│   └── weather.ts        #   天气工具示例
├── utils/                # 工具函数
│   ├── config.ts         #   配置创建与校验
│   ├── message.ts        #   消息处理中心 (tool_calls → 工具执行 → ToolMessage)
│   ├── tool.ts           #   工具调用执行 (useTool)
│   └── dotenv.ts         #   环境变量加载配置
├── prompts/              # 提示词管理
│   └── system.ts         #   系统提示词
├── types/                # 类型层
│   ├── index.ts          #   类型导出入口
│   ├── llm/              #   统一 LLM 抽象类型
│   │   ├── message.ts    #     LLMMessage, LLMSystemMessage, LLMUserMessage, ...
│   │   ├── request.ts    #     LLMRequest
│   │   ├── response.ts   #     LLMResponse, LLMUsage
│   │   └── tool.ts       #     LLMTool, LLMToolChoice
│   ├── providers/        #   Provider 接口 + 提供商特定类型
│   │   ├── index.ts      #     Provider, LLMAdapter 接口
│   │   └── deepseek.ts   #     DeepSeek 请求/响应/消息类型
│   └── config/           #   配置类型
│       └── index.ts      #     RuntimeConfig, TaskConfig, Config
└── const/                # 常量
    └── path.ts           #   .env 文件路径
```
